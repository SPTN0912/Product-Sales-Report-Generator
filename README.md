# Product Sales Report Generator

A Java-based command-line application that processes daily product sales data from CSV files and generates comprehensive sales summary reports. The application provides revenue analysis at both product and category levels and identifies key sales performance indicators.

## Features

* Read product sales data from CSV files
* Automatically handle CSV header rows
* Calculate total revenue for each product
* Calculate total revenue for each category
* Identify the best-selling product based on quantity sold
* Identify the highest-revenue product
* Calculate the grand total revenue
* Display reports directly in the console
* Save generated reports to a text file
* Handle invalid input and file-related errors gracefully
* Support unit testing for core business logic
* Follow clean code and SOLID design principles
* Designed for easy extension with additional output methods

* **Java** – Application development

## Input Format

The application accepts a CSV file containing product sales information with the following columns:

```text
product_id, product_name, category, quantity_sold, unit_price
```

Example:

```text
P001, Wireless Mouse, Electronics, 12, 25.50
P002, Notebook, Stationery, 35, 3.75
P003, USB Hub, Electronics, 8, 18.00
P004, Ballpoint Pen, Stationery, 100, 0.50
P005, HDMI Cable, Electronics, 20, 12.00
```

## Generated Report

The application generates a formatted report containing:

### Revenue Per Product

Displays the total revenue generated by each product.

### Revenue Per Category

Displays the combined revenue generated by products within each category.

### Sales Highlights

The report identifies:

* Best-selling product
* Highest-revenue product
* Grand total revenue

## Usage

The application follows the command-line format:

```bash
java SalesReporter <csv-file-path> <output-method> [output-file-path]
```

### Display Report in Console

```bash
java SalesReporter sales.csv console
```

### Save Report to a File

```bash
java SalesReporter sales.csv file report.txt
```

The output file path is required when the `file` output method is selected.

* Missing required command-line arguments

## Design Principles

The application follows software development best practices, with particular attention to:

* **Single Responsibility Principle**
* **Open-Closed Principle**
* Separation of business logic from input/output operations
* Interface-based design for extensibility
* Meaningful naming and clean code
* Maintainable and testable components

The CSV processing and application components are designed according to SOLID principles. The output functionality is structured so that additional output methods can be introduced in the future with minimal changes to the existing code.
